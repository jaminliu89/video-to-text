# 蒸馏方法（Distill）— 固定管线规范 v1.0

> 这是 VideoToText 第三种模式的"方法说明书"。
> 代码在 `v2t/distill.py`，提示词在 `v2t/distill_prompts.py`。
> **改了阶段顺序、阈值或 schema，就等于改了方法本身**，请同步更新本文件。

---

## 0. 一句话

给一个文件夹，产出四件东西：**去重后的逐字稿**、**这批视频到底讲了什么**、**可迁移的方法论**、
**（若涉及产品）它的架构与商业模式**。

它不是"把视频转成文字"的加强版，而是**把一堆散乱视频变成一份可以拿去决策的认知包**。

---

## 1. 为什么需要固定方法

随手丢给 LLM "帮我总结这些视频"必然失败，原因有三个：

| 失败模式 | 后果 | 本方法的对策 |
|---|---|---|
| 视频有重复（改名、重录、不同压制） | 同一内容被算两次，权重失真 | S1 三层去重 |
| 逐字稿里大量重复开场/口播套话 | 上下文被垃圾占满，真信息被挤掉 | S3 语句级去重 |
| 直接要"方法论" | LLM 复述操作步骤，产出没有迁移价值 | S6 强制分层 L0→L3，并禁止用产品名代替方法 |

所以本方法的核心不是"用哪个模型"，而是**先做减法和分层，再做抽象**。

---

## 2. 输入契约

| 项 | 要求 |
|---|---|
| 输入 | 一个文件夹路径，**可含任意层级子目录** |
| 文件 | `mp4/mov/mkv/avi/flv/webm/m4v/wmv/ts`，> 512KB |
| 忽略 | `._*`（macOS 资源分叉）、隐藏文件、非视频文件 |
| 规模 | 1 个到几十个视频；总时长 10 分钟到 10 小时都跑得动 |
| 语言 | 中文为主（ASR 固定 `language=zh`） |
| 可选 | 热词纠正表 `--hotwords "错=对,错2=对2"`，修专有名词误听 |

任意文件夹都能跑，是因为**所有阶段都不依赖文件名规律**：
文件名只用来生成可读标题（`clean_title`），真正的判据是内容哈希、画面指纹、逐字稿文本。

---

## 3. 八阶段

```
S0 采集 → S1 去重 → S2 转写 → S3 合并 → S4 深读 → S5 综合 → S6 抽象 → S7 逆向 → S8 产出
   ↑________↓ 每阶段结果落盘 _work/，支持断点续跑 ________↓
```

### S0 采集（Collect）

- 递归扫描，读时长/宽高/音轨/大小
- `clean_title()` 把 `星月写作教程 - 【星月写作教程】Ai提示词_提示词的使用教程·百万字…` 洗成 `Ai提示词_提示词的使用教程`
  （去掉平台前缀 → 去【】→ 砍 `·` 之后的营销尾巴）
- 产出：视频清单，分配稳定 ID `V01…Vnn`（按相对路径排序，保证可复现）

### S1 去重（Dedupe）— 三层，逐层收紧

| 层 | 判据 | 阈值 | 抓什么 |
|---|---|---|---|
| L1 文件级 | 文件内容 SHA-256 | 完全一致 | 同一文件被复制/改名 |
| L2 近似级 | 时长差 + 3 帧 dHash 汉明距离 | 时长差 ≤2% 且 平均汉明 ≤6 | 同一内容的不同压制、剪辑版、转码版 |
| L3 内容级 | 逐字稿 5-gram Jaccard | ≥0.80 | 同一门课被重录、同一场直播的两个切片 |

保留策略：**保留信息量最大的一条**（L1 取文件最大、L2 取文件最大、L3 取字数最多）。
被丢弃的记 `duplicate_of` + `duplicate_reason`，写进 `dedupe_report.md`，可复查。

> 为什么用 dHash 而不是 pHash：dHash 8×8 只比相邻像素，对亮度/压缩不敏感，
> 而 pHash 需要 DCT，在 320px 缩略图上反而不稳。3 帧（15%/50%/85%）足以区分"同源"与"同主题"。

### S2 转写（Transcribe）

- 抽 16k 单声道 wav → faster-whisper（默认 `base`，int8，CPU）
- 缓存键 = 文件 SHA-256 前 12 位 + 引擎 + 模型，换模型不会串结果
- 速度参考：M 系列 CPU 上 `base` ≈ 7 倍速（1.6 小时视频约 13 分钟），`large-v3-turbo` ≈ 1.7 倍速
- 失败降级：该视频标记无逐字稿，后续阶段跳过它，不中断整批

**热词纠正（可选但强烈建议）**：中文 ASR 对专有名词是系统性误听
（实测把"星月写作"听成"新约写作"14 次）。换更大的模型能改善但代价 3-8 倍时间，
用一张纠错表更划算：

```bash
--hotwords "新约写作=星月写作,新约=星月"
```

规则在 S2 之后、S3 之前统一应用，长词优先替换（避免"新约"先吃掉"新约写作"的一部分），
且**幂等**。热词表或提示词版本变化时，`_work/_meta.json` 的签名不匹配，
S3-S7 的中间结果自动作废重跑，转写缓存保留。

### S3 合并（Merge）— 跨视频语句级去重

这是"合并"的实质，不只是拼接：

1. 逐句归一化（只留中日韩/字母/数字），生成 5-gram 指纹
2. 维护"已收录指纹全集"，新句子的指纹 **包含率 ≥85%** 即判定为重复 → 丢弃并计入该视频的 `redundant`
3. 纯语气词、短句里的求关注/版权声明 → 噪声丢弃（长句里出现"关注"不算）
4. 段落化：同一视频、间隔 ≤1.6s、当前段 <200 字 → 合并成段

产出 `01_逐字稿合并.md`，每段带锚点 `[V03 04:12]`，可回查原视频位置。

> 这一步砍掉的是"19 个视频都讲了一遍怎么点按钮"这类内容，
> 保留的是每个视频独有的一段。`dedupe_report.md` 里能看到每条视频被砍了多少句。

### S4 深读（Analyze）— 单视频结构化拆解

固定 schema（见 `distill_prompts.ANALYZE_VIDEO_SCHEMA`）：

| 字段 | 作用 |
|---|---|
| `gist` / `one_line_takeaway` | 一句话说清 + 一句话记住 |
| `sections` | 章节切分（带时间戳） |
| `steps` | **可照着做的操作步骤**（动作 / 在哪做 / 参数 / 原话） |
| `concepts` | 术语与定义 |
| `rules_and_numbers` | 价格、字数、额度、比例，**原样保留** |
| `ui_evidence` | 画面里的界面元素（按钮/字段/面板） |
| `pitfalls` | 讲师亲口说的坑与限制 |
| `claims` | 可验证的主张/承诺 |
| `open_questions` | 没讲清、需要外部验证的点 |

硬约束：**只能基于材料推断，没证据就留空**；原话引用必须与逐字稿一致。
长逐字稿（>12000 字）做首尾截断保语义完整，避免超上下文。

并发：LLM 调用是网络 IO，默认 3 并发（`--concurrency`）。ASR 是 CPU 密集，串行。

### S5 综合（Synthesize）— 跨视频关系层

| 产出 | 含义 |
|---|---|
| `topics` | 主题地图，带重要度（1-5）与覆盖视频 |
| `knowledge_units` | **知识单元**：同一知识点在不同视频里的碎片，合并成一条完整的；合并后仍有分歧写进 `conflicts` |
| `redundancy` | 反复出现的开场、被重复讲的内容、**只有某条视频才有的信息** |
| `conflicts` | 说法不一致的地方 + 如何判断 |
| `learning_path` | 建议观看顺序与理由 |
| `missing_pieces` | 这批视频都没讲、但要做好这件事必须知道的 |
| `master_summary` | 300-600 字综述：讲什么、怎么讲、值不值得学、学完能做什么 |

规则兜底：LLM 不可用时用 TF 词频聚类（`topic_clusters`）给出关键词簇主题，不空转。

### S6 抽象（Methodology）— 四层，禁止跳层

这是最容易被做坏的一步。要求把"操作"抬成"方法"：

| 层 | 内容 | 反例 | 正例 |
|---|---|---|---|
| L0 事实 | 视频里确凿的操作与数字 | — | 「续写前必须选章纲」 |
| L1 规律 | 从事实归纳的一般规律 | — | 「先约束后生成，比生成后改更省 token」 |
| L2 方法 | 可复用的流程（别人照着能做） | 「用星月的续写功能写章节」 | 「定章节目标 → 给约束 → 生成 → 只改冲突点」 |
| L3 模型 | 底层心智模型 | — | 「长篇的一致性靠结构化状态，不靠模型记忆」 |

产出：
- `master_method`：总方法（问题 / 前提 / 整体逻辑 / 阶段流程：目标·动作·产出·验收·做错的后果）
- `method_cards`：4-10 张子方法卡，每张必须有 `anti_patterns`（反模式）与 `transfer`（迁移到别的领域怎么用）
- `mental_models` / `decision_table`（if-then 决策表）/ `quality_bar`（可检验的质量线）

**判定标准**：方法卡里出现产品名即为失败——那还是操作，不是方法。

### S7 逆向（Product）— 只在"涉及产品"时才做

触发判定（两路取并集，任一路成立即做，LLM 有最终否决权）：
- 规则信号：`会员/套餐/充值/字数包/额度/消耗/价格/界面/按钮/面板…` 词频累计 ≥12 且命中 ≥4 类
- LLM 判定：`is_product`

逆向的四条推理链（写进提示词，防止拍脑袋）：

| 推理方向 | 从 | 到 |
|---|---|---|
| 功能 → 模块 | 用户能看到的功能 | 背后必须存在的数据结构与服务 |
| 卖点 → 收费 | 讲师反复强调的卖点 | 计量单位与套餐结构 |
| 教学步骤 → 摩擦 | 必须教的每一步 | 产品没做好的地方（需要教 = 有摩擦） |
| 数字 → 定价 | 逐字稿里的硬数字 | 定价表与成本结构 |

产出：定位（是什么/给谁/替谁完成什么任务/切入点/替代方案）、
架构（分层模块、数据对象、核心流程、AI 链路推测、mermaid 图）、
商业模式（收入结构、定价表、计量单位、成本与毛利推测、会被薅羊毛的点、获客/漏斗/留存）、
护城河、风险、复刻路径（MVP 周期 / 必须有 / 可以有 / 第一期别做 / 最难的不是功能 / 前 10 个用户从哪来）、
待验证假设。

### S8 产出（Emit）

```
output/<分类>/<批次>/
  00_总览.md          # 一页看懂：数字、主题地图、知识单元、冗余、冲突、缺口、学习路径、综述
  01_逐字稿合并.md     # 去重合并后的逐字稿，带 [V03 04:12] 锚点
  02_方法论.md        # 总方法 + 方法卡 + 心智模型 + 决策表 + 质量线 + 四层拆解
  03_产品逆向.md      # 定位 / 架构(mermaid) / 商业模式 / 复刻路径 / 待验证
  04_证据索引.md      # 硬数字表 + 每条视频的章节/步骤/界面线索/坑/原话
  dedupe_report.md    # 三层去重明细 + 每条视频被砍了多少句
  dedupe_report.json
  distill.json        # 全量结构化数据（给 Agent / 二次加工）
  transcripts/
    V01_<标题>.md / .srt / .txt
  _work/              # 各阶段中间结果（断点续跑用，可删）
```

## 4. 可复现性

| 机制 | 说明 |
|---|---|
| 固定阈值 | 全部集中在 `distill.THRESHOLDS`，不散落 |
| 固定 schema | 字段名锁死在 `distill_prompts.SCHEMAS`，下游渲染不会漂 |
| 版本号 | `PIPELINE_VERSION` + `PROMPT_VERSION` 写进 `distill.json` 与文件头 |
| 稳定排序 | 视频按相对路径排序编号，同一批文件每次得到同样的 V01/V02 |
| 断点续跑 | 每阶段落盘 `_work/`，`--resume`（默认）跳过已完成；`--fresh` 全重跑 |
| 降级不污染缓存 | LLM 不可用时的规则结果**不写缓存**，等有 LLM 时自动重跑 |

LLM 有随机性，所以"同一批视频两次跑出逐字相同的 02_方法论.md"不现实；
但**输入判定（去重/合并/数字抽取）是确定性的**，同一批文件每次结论一致。

## 5. 换 LLM

只认 OpenAI 兼容协议，按优先级自动回落：

1. `DISTILL_LLM_BASE` + `DISTILL_LLM_KEY` + `DISTILL_LLM_MODEL`（任意兼容端点：Gemini / DeepSeek / 本地 vLLM / one-api）
2. 硅基流动（`SILICONFLOW_API_KEY` + `LLM_MODEL`）
3. 火山方舟（`ARK_API_KEY` + `ARK_VIDEO_ENDPOINT`，方舟 endpoint id 可直接当 model 用）

一个都不配也能跑：S1/S2/S3 全量产出，S4-S7 降级为规则结果，管线不崩。

### 思维链（thinking）开关

推理型模型（豆包 seed、DeepSeek-R1 等）默认会先"想"再答，代价是 3-5 倍延迟。
本管线默认**全阶段关闭**思维链，理由是实测：8000 token 的抽象任务开着 CoT
在慢端点上单次要 10 分钟以上，直接撞超时；关掉后同样任务 2-4 分钟，JSON 质量差别不大。

| 阶段 | 默认 | 理由 |
|---|---|---|
| S4 深读 | 关 | 结构化抽取，照着 schema 填 |
| S5 综合 | 关 | 归纳合并，材料都在眼前 |
| S6 抽象 | 关 | 慢端点上开 CoT 会超时 |
| S7 逆向 | 关 | 同上 |

`DISTILL_THINKING=on` 全局打开（模型快、要质量时用），`=off` 强制全关。
实测：同一端点，关掉思维链后单个视频深读从 155s 降到 ~50s。
调用超时按输出预算自动放大（`180 + max_tokens × 0.15` 秒），避免长输出被 5 分钟掐断。

## 6. 已知局限

1. **ASR 是天花板**。`base` 快但会错专有名词（"计费"→"济费"）。要准就 `--whisper-model small/large-v3-turbo`，代价是 3-8 倍时间。
2. **画面只做去重，不做理解**。本模式以音频语义为主；画面理解请用"深度拆解"模式的豆包/关键帧引擎。
3. **产品逆向是推测**。`03_产品逆向.md` 里的定价、毛利、AI 链路都标了推测，别当事实用。
4. **长视频单次调用会截断**（>12000 字）。极端长视频建议先切片再蒸馏。
5. **跨视频冲突检测依赖 LLM**，规则层只做重复不做矛盾。
