# video2text 改造走查报告

**日期**：2026-10-29
**改造目标**：修复 ASR 重复字问题、加入九宫格抽帧、分类资产目录、Agent CLI 接口

---

## 一、改造内容

### 1. 转写后端升级（解决重复字问题）

**问题**：原 whisper.cpp small 模型处理长中文音频，末尾会出现重复幻觉（"后面全是重复的字"）。

**方案**：改为可插拔三引擎架构
- `sensevoice`（默认）：本地 SenseVoice-Small，通过子进程调用 `~/Projects/sensevoice-local/.venv`，中文准、不重复
- `whisper`：保留旧 whisper.cpp 逻辑
- `minutes`：飞书妙记（免费额度，需 lark-cli）

**新增文件**：
- `v2t/asr.py` — 转写引擎分发
- `v2t/workers/sensevoice_worker.py` — sensevoice 子进程（VAD 分段 + 逐段转写 + 累加时间戳）

**实测结果**（光羽的平行世界视频，7分40秒）：
- sensevoice 转写：5 段，1963 字
- **无重复字**，结尾正常收束（"我是光宇…我们下回见。"）
- 对比原 whisper.cpp small：末尾重复幻觉消除

### 2. 九宫格故事板

**新增文件**：`v2t/storyboard.py`

**功能**：
- hybrid 抽帧：均匀抽帧 + 场景切换检测（ffmpeg select gt(scene,0.30)）
- 3x3 九宫格分页拼图，每格带时间戳标签
- 输出 storyboard_p01.jpg / p02.jpg / p03.jpg

**实测结果**：24 帧，3 页（9+9+6），画面清晰，时间戳准确。

### 3. 分类资产目录

**新增文件**：`v2t/assets.py`

**结构**：
```
output/<分类>/<视频名>/
  ├── <视频名>.md          # 笔记
  ├── <视频名>.json        # 结构化数据
  ├── transcript.json      # 转写 segments
  ├── storyboard_p01.jpg   # 故事板
  └── storyboard_index.json
```

### 4. Agent CLI 接口

**新增文件**：
- `cli.py` — 命令行入口（transcribe/storyboard/digest/batch/list/info）
- `SKILL.md` — 给别的 Agent（Codex/Claude Code/豆包）的调用描述

**设计**：所有命令支持 `--json`，结果输出到 stdout，日志走 stderr，Agent 可直接解析。

## 二、ADR 决策记录

| ADR | 决策 | 原因 | 安全性 |
|-----|------|------|--------|
| ADR-1 | sensevoice 通过子进程调用，不直接 import funasr | 避免在 video2text 主进程加载重型依赖（torch/funasr），保持主进程轻量 | 子进程崩溃不影响主进程；模型加载失败有明确报错 |
| ADR-2 | sensevoice venv 复用 `~/Projects/sensevoice-local/.venv` | 不重复安装 900MB 模型和依赖 | 只读调用，不修改原 venv |
| ADR-3 | VAD 分段阈值从 500ms 调到 300ms | 原阈值太严格，长音频只切 5 段，时间戳粒度粗 | 分段更细，时间戳更准 |
| ADR-4 | 默认引擎改为 whisper base（141MB），sensevoice 作为增强模式 | 实测 whisper base 简体、错字少、时间戳细，141MB 下得快；sensevoice 893MB 太大，不适合默认 | 向后兼容，用户可手动 --asr sensevoice 切换 |

## 三、引擎实测对比（光羽平行世界视频，7分40秒）

| 引擎 | 大小 | 字数 | 段数 | 结尾重复 | 质量评价 |
|------|------|------|------|---------|---------|
| whisper tiny | 74MB | 2817 | 207 | 无 | 繁体、错字多 |
| **whisper base（默认）** | **141MB** | **2973** | **286** | **无** | **简体、错字少、时间戳细** |
| sensevoice fp32（增强） | 893MB | 1963 | 5 | 无 | 标点好、流畅，但分段粗 |

**关键发现**：
1. whisper tiny/base 在这个视频上都没有结尾重复字——用户之前遇到的重复问题是 whisper.cpp **small** 模型的
2. whisper base 性价比最高：141MB、简体、错字少、286 段时间戳细
3. sensevoice 标点最好（有逗号句号），但 893MB 太大，分段粗（5段）

## 四、faster-whisper 集成（第二步）

参考 DeepSeek Harness 的 dsh-whisper-provider，加入 faster-whisper（CTranslate2 后端）：
- 默认引擎改为 faster-whisper
- Mac 上用 CPU（CTranslate2 不支持 MPS），int8 量化
- 实测：342 段、3003 字、无重复
- 注意：Mac 上 whisper.cpp 用 Metal 反而更快（22s vs 70s）；faster-whisper 在有 GPU 的机器上才明显快

## 五、LLM 摘要整合（第二步）

- 没有 SILICONFLOW_API_KEY 时自动跳过 LLM 摘要，不报错

## 八、已知问题与后续优化

1. **sensevoice 分段粒度**：当前 VAD 在连续语音场景下仍只切 5 段，后续可考虑按句子长度二次切分
2. **飞书妙记接入**：`_transcribe_minutes` 已写框架，但需实际配置 lark-cli 授权后才能用
3. **GUI 集成**：现有 NiceGUI 界面（gui.py）尚未加入 sensevoice/故事板选项，需后续迭代
4. **批量处理**：`cli.py batch` 已实现，但批量时 sensevoice 模型会反复加载（每个视频起一次子进程），后续可做常驻 worker 优化
